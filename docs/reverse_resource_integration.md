# 逆向资源接入与功能实现

本次修改保持 `455×256` 单字节索引画面、C/C++ 静态资源和 `BaseRender`
场景栈架构。地图的原始.cpp/.h文件和数组直接保留；精灵由重新生成的 ROM 图像替换，并通过独立调色板映射进入现有绘制管线。

## 资源入口与精灵格式

已按工程原有组织方式恢复maps：`tile_bmp.cpp/.h`、240张`map_N.cpp/.h`
、索引表及水面数据均保持原始字节，并重新作为游戏的直接数据源。它们没有经过bin2c转换或压缩。

新增资源按模块、记录分别生成头文件：精灵CHR按bank，特殊/系统模型按编号；NPC按地图组；脚本逐条；文字按页、字库按源bank；怪物图像逐个；物品按装备/工具类型；商品清单按类别/页。公共
`game_data.h`只声明API和小型值结构，`game_data.cpp`只转发查询，均不集中定义资源数组。

资源生成入口为 `tools/import_reverse.py`。工具不会写入`app/src/main/cpp/maps`
，JSON仅作为开发输入/校验报告。APK无assets/JSON。原数据组织和校验详情见 [按模块组织的bin2c资源](bin2c_resource_layout.md)。

## NPC活动与脚本

`sprite/map_npcs` 为当前地图建立独立运行时对象，包含图块/像素坐标、方向、步态、显示状态、属性与动态脚本程序计数器。

- 主角每逻辑tick推进2像素，一格8tick完成；脚本NPC默认每2tick推进1像素，一格32tick完成；被主角推动的NPC跟随主角速度，避免推动时角色重叠。
- 支持闲逛、追踪目标、指定坐标移动、传送、朝向、朝向玩家、原地动作和事件等待。
- 保留X bit7锁定朝向、X bit6禁止步行动画；Y高位转换为可推动和忽略地形标志。
- 空图像和隐藏控制器不参与显示或阻挡；有图像NPC参与通行与推移检查。
- 菜单/对话在栈顶时地图逻辑暂停；地图仍从下层绘制。

固定NPC不会统一随机活动。动作0保持静止；动作1执行原地活动；动作2按脚本闲逛。复杂动态动作遇到尚未实现的指令会停止这条脚本并记日志，避免越过未知行为继续修改剧情状态。

当前脚本转换覆盖事件置位/清除、条件文字、位置/事件/队伍/等级/金钱/物品判断、是/否、跳转、重复、时间/事件等待和上述NPC基础动作。静态游戏ID1..108按editor索引减1查询，动态ID0..168直接查询。条件跳转和标签保留，不能把所有分支文字串联显示。

转换器标记80条动态、88条静态脚本没有未实现指令屏障。这个计数表示当前表转换的覆盖，并不证明这些剧情已经完整复现；剩余89条动态、20条静态脚本具有未实现指令。战车条件在尚无战车状态时为false，相关块跳过。

## 可操作功能

标题动画后进入“开始新游戏 / 继续游戏”，上/下选择、A确认。初始玩家位置为世界地图 `(91,232)`，由原始入口进入城镇。

地图按A打开菜单：

| 菜单 | 行为                               |
|----|----------------------------------|
| 交谈 | 面前NPC转向玩家；普通文字翻页，静态脚本执行条件与是/否    |
| 装备 | 从物品栏选择人类装备，按类别替换，保留被替换装备并更新攻击/防御 |
| 状态 | 人物等级、HP、攻击、防御、经验、金钱              |
| 调查 | 面前宝藏、计算机或NPC；宝藏领取后保留已领取标志        |
| 物品 | 32格物品栏；基础恢复物品和装备操作               |
| 保存 | 将当前地图位置、人物、物品、事件和宝藏状态写入应用私有目录    |

支持人类装备店、工具店、药店和道具售货机数据的购买。购买前检查价格、数量、金钱与空槽，失败不扣钱或部分添加。旅馆有基本休息恢复。

NPC服务分支接入保存、读取、治疗和查看剩余升级经验；其他类型保留为未开放提示。地图计算机的独立控制表编号仍显示原始类型，不把它误按NPC
talk1位域解析。控制室、密码、改装、战车服务等没有当成普通治疗或保存处理。

存档文件是 `filesDir/metalmax-v1.sav`
，带magic、版本、结构长度与CRC32，当前写v2紧凑布局并兼容读取v1。写入先写临时文件、flush/fsync，再原子替换。读取校验字段和校验和，坏存档不覆盖当前状态。格式面向当前Android构建，结构变化需升级版本。

战斗场景新增攻击、防御、物品、逃跑、HP变化和胜负结果；胜利结算解码后的经验/金钱，脚本战斗可置位结果事件。Debug的“ENTER
BATTLE”继续保留怪物图鉴浏览，方便资源检查。

## 地图和引擎修正

地图贴图的像素和布局保持原样。通行读取单独的map_attributes，避免依赖旧feature数组；去除了`|| true`
穿墙。原入口多重记录与LAST/FIXED/DIRECTION边界目标已导入，返回历史改为有边界检查的容器。

地图通过原有short_map_data和bitmaps读取，按可见图块直接复制到455×256索引画面；没有地图数据解码步骤。位图、门相关绘制、文字绘制都有屏幕范围检查。切图在逻辑tick中执行，亮度按tick计算，统一到0..100。

场景栈使用递归mutex协调逻辑与绘制，删除推迟到回调完成后。修正MapRender类型判断，空栈安全，初始化避免重复线程。Surface销毁先等待渲染线程，再释放画面、调色板与ANativeWindow；EGL和纹理显式释放。Activity暂停时暂停逻辑和播放输出，触摸取消/拖动释放状态。

音频仍使用原项目的NSF方案。背景与音效分开NSF对象，曲目请求在解码线程应用，换曲清缓存；音效不再每次建线程。PCM缓存复制到OpenSL自身buffer，空数据用静音补充，取消跨线程mutex解锁，暂停后销毁OpenSL对象。音效当前以约1.024秒的最大混音窗口处理，精确结束事件仍待接入。

## 验证记录

主机测试 `tools/test_host.py`
使用小型Android图形/声音接口替身，执行真实C++资源和游戏逻辑，开启AddressSanitizer与UndefinedBehaviorSanitizer。角色贴图以 [2026-10-22复核记录](sprite_review.md)
为准。

已验证：

- 5,544个普通精灵姿态与ROM实际6502例程生成的OAM渲染逐像素一致，覆盖11组CHR、63类图像、四向、两帧，包含模型50。
- 1,353个特殊/系统模型组合的位置、透明、翻转、颜色和覆盖顺序与原ROM例程一致；主角实际路径使用模型09。
- 主角、脚本NPC、被推动NPC的移动时长分别按8tick、32tick、8tick验证；NPC动作2真实移动且出现第二帧，锁定朝向和禁用步态标志生效。
- 事件08的两种文本分支、场景切换关闭对话、装备数值变化与恢复物品消耗。
- 保存/读取、坏CRC存档拒绝、商店购买、世界入口进入地图1、碰撞与切图亮度范围。
- 240张地图缓存与精灵绘制，完全在屏幕外的位图裁剪；基础战斗只结算一次。
- 当前NDK29 arm64原生库和Android Java编译通过。
- Debug APK打包与签名成功，含arm64原生库、DEX和导入资源。

489个原始maps数据及头文件保持原路径、原始字节；原全局调色板也已恢复。工具运行前后校验maps内容未改写。主机截图在同级
`metalmax-analysis/host-tests/`。

`tools/build_debug.py` 已按当前工程的Gradle8.12、AGP8.10.1、SDK35和NDK29构建，使用Android
Studio的完整JBR21，正常执行JavaCompile及原生库、DEX和APK打包。旧Gradle/JDK11的javac替换路径仅在旧版本配置下使用。工具读取现有wrapper版本，不修改工程的Gradle版本或SDK配置。产物为同级
`metalmax-analysis/metalmax-debug.apk`。

```bash
python3 tools/build_debug.py
```

## 尚未完成的范围

基础战斗公式、逃跑概率、每级成长和恢复物品效果是明确的重制基础规则，目前不是原版6502规则的完整移植。战斗当前一个怪物、主角行动；其他队员虽可记录和展示，尚未形成完整队伍行动系统。怪物AI、技能、状态异常、SP/战车/牵引/改装、完整装备特殊效果和所有音频指令未完成。

剧情尚未实现的关键指令包括控制切换、菜单服务、区域触发、复杂动画、图块事件、战车操作、场景切换和结尾流程等。原始数据和分析材料均已保存，未将未知分支当作完成。

宝藏中编码大于物品范围的奖励没有直接当物品领取，避免发放错误数值。地图贴图差异遵从用户要求保留，未重新生成或替换。Android真机GPU输出、触控多指组合和音频听感还需要设备验证；主机测试不替代这些硬件检查。
