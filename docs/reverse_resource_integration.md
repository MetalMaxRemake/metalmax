# 逆向资源接入与功能实现

本次修改保持 `455×256` 单字节索引画面、C/C++ 静态资源和 `BaseRender`
场景栈架构。地图的原始.cpp/.h文件和数组直接保留；精灵由重新生成的 ROM 图像替换，并通过独立调色板映射进入现有绘制管线。

## 资源入口与精灵格式

已按工程原有组织方式恢复maps：`tile_bmp.cpp/.h`、240张`map_N.cpp/.h`
、索引表及水面数据均保持原始字节，并重新作为游戏的直接数据源。它们没有经过bin2c转换或压缩。

新增资源按模块、记录分别生成头文件：精灵CHR按bank，特殊/系统模型按编号；NPC按地图组；脚本逐条；文字按页、字库按源bank；怪物图像逐个；物品按装备/工具类型；商品清单按类别/页。公共
`game_data.h`只声明API和小型值结构，`game_data.cpp`只转发查询，均不集中定义资源数组。

资源生成入口为 `tools/import_reverse.py`。工具不会写入`app/src/main/cpp/maps`
，JSON仅作为开发输入/校验报告。APK无assets/JSON。原数据组织和校验详情见 [按模块组织的bin2c资源](bin2c_resource_layout.md)。

## NPC活动与脚本

`sprite/map_npcs` 为当前地图建立独立运行时对象，包含图块/像素坐标、方向、步态、显示状态、属性与动态脚本程序计数器。

- 主角每逻辑tick推进2像素，一格8tick完成；脚本NPC默认每2tick推进1像素，一格32tick完成；被主角推动的NPC跟随主角速度，避免推动时角色重叠。
- 支持闲逛、追踪目标、指定坐标移动、传送、朝向、朝向玩家、原地动作和事件等待。
- 保留X bit7锁定朝向、X bit6禁止步行动画；Y高位转换为可推动和忽略地形标志。
- 空图像和隐藏控制器不参与显示或阻挡；有图像NPC参与通行与推移检查。
- 菜单/对话在栈顶时地图逻辑暂停；地图仍从下层绘制。

固定NPC不会统一随机活动。动作0保持静止；动作1执行原地活动；动作2按脚本闲逛。当前277条动态/静态脚本均可转换为明确VM指令，不再生成未实现指令屏障。

当前脚本转换覆盖事件置位/清除、条件文字、位置/区域/朝向/事件/队伍/等级/金钱/物品/宝藏/HP/探测器/战车判断、是/否、跳转、重复、时间/事件等待和上述NPC基础动作。静态游戏ID1..108按editor索引减1查询，动态ID0..168直接查询。条件跳转和标签保留，不能把所有分支文字串联显示。

新增 `story_runtime` 承接剧情运行期副作用：控制锁、音乐/音效、菜单服务、玩家显示/变身/传送/牵引、地图tile覆盖、开门、队伍加入/离开、睡觉/次日和探测器。战车状态已下沉到
`game_state`，剧情条件与地图/菜单共用同一份存档状态。`DrawTile`、`OpenDoor` 等只写内存覆盖层，原始
`maps/` 数据和贴图文件保持不变。

## 可操作功能

标题动画后进入“开始新游戏 /
继续游戏”，上/下选择、A确认。新游戏进入起名页，确认后保存主角名，进入主角家地图3并加载开场NPC组240；父亲、妹妹和主角的动态脚本10/11/12按事件位推进，完成“主角被父亲赶出家门”剧情后由
`#scene 0x02` 切到后续开场组，并在 `#nextday` 后回到可操作地图。继续游戏仍从存档恢复当前地图和状态。

地图按A打开菜单：

| 菜单 | 行为                                                  |
|----|-----------------------------------------------------|
| 交谈 | 面前NPC转向玩家；普通文字翻页，静态脚本执行条件与是/否                       |
| 装备 | 在已入队角色之间切换，从该角色携带物品中选择人类装备，按类别替换，保留被替换装备并更新该角色攻击/防御 |
| 状态 | 仅显示已入队角色的人物等级、HP、攻击、防御、速度、经验、装备和携带物品                |
| 调查 | 面前宝藏、计算机或NPC；宝藏领取后保留已领取标志                           |
| 物品 | 每名已入队角色8格携带物品；支持按角色切换、基础恢复物品、装备和可丢弃物品               |
| 战车 | 已拥有战车的SP、防御、攻击、载重、炮弹、位置、装备和乘坐/牵引状态                  |
| 车装 | 从车载物品中选择战车装备，装入主炮、副炮、S-E、C装置、发动机或底盘槽                |
| 保存 | 将当前地图位置、人物、物品、事件和宝藏状态写入应用私有目录                       |

支持人类装备店、工具店、药店和道具售货机数据的购买。购买前检查价格、数量、金钱与已入队角色空槽，失败不扣钱或部分添加。旅馆有基本休息恢复。未入队角色保留其原始初始数据，但不出现在状态/装备/物品界面中，身上的物品也不参与队伍物品判断。

战车初始装备、SP、防御、重量、炮弹、地图和坐标从 `tankEditor`
导出的bin2c数据初始化。地图上可看见已拥有战车，步入相邻战车会进入并驾驶；乘车调查可下车；面前战车调查可开始/停止牵引，牵引车跟随到角色移动前的位置。战车装备/道具购买和宝藏/脚本入包会优先进入当前乘坐战车或第一辆已拥有战车。

NPC服务、脚本 `#menu`
和地图计算机统一进入服务分发。16类列表服务均已接入：战车装备、战车工具、人类装备、人类工具、出租战车、特殊炮弹、旅馆、酒吧、装饰店、点唱机、道具售货机、炮弹售货机、装甲片售货机、药店和电梯。交互服务接入保存/读档、老爹、明奇、战车底盘/发动机改装、猎人事务所、保管所、修车、募捐、激光炮终端、战车贩卖、传送装置、清洗、按摩、出租战车回收、赌博机、存档小姐、升级经验、控制室和NOA密码终端。地图
ComputerEditor 的类型号仍按独立计算机编号处理，0..15 走时空传送目的地，0x10..0x3f 走赌博/小游戏，0x40..0x7c
可直接打开对应列表服务，其他控制终端置位相应事件并给出可见反馈。

存档文件是 `filesDir/metalmax-v1.sav`
，带magic、版本、结构长度与CRC32，当前写v5布局，每名角色保存独立8格携带物品和角色名，8辆自有战车保存位置、装备、车载物品、SP、乘坐和牵引状态，并兼容读取v1/v2/v3/v4旧布局。旧版全局物品栏会在读取时迁移到已入队角色携带栏，剩余物品保留在兼容背包中；旧存档战车状态按ROM初始数据补齐，角色名补默认名。写入先写临时文件、flush/fsync，再原子替换。读取校验字段和校验和，坏存档不覆盖当前状态。格式面向当前Android构建，结构变化需升级版本。

战斗场景现在区分步战和车战。步战支持已入队角色轮转行动、攻击、防御、战斗内使用恢复物品、战斗内更换人物装备和逃跑；车战在乘坐战车时进入，支持炮击、防御、车载道具、战斗内更换战车装备、下车切回步战和逃跑。敌方攻击会优先扣战车SP，SP耗尽后溢出到乘员HP；胜利结算解码后的经验/金钱，脚本战斗可置位结果事件。Debug的“ENTER
BATTLE”继续保留怪物图鉴浏览，方便资源检查。

## 地图和引擎修正

地图贴图的像素和布局保持原样。通行读取单独的map_attributes，避免依赖旧feature数组；去除了`|| true`
穿墙。原入口多重记录与LAST/FIXED/DIRECTION边界目标已导入，返回历史改为有边界检查的容器。

地图通过原有short_map_data和bitmaps读取，按可见图块直接复制到455×256索引画面；没有地图数据解码步骤。位图、门相关绘制、文字绘制都有屏幕范围检查。切图在逻辑tick中执行，亮度按tick计算，统一到0..100。

场景栈使用递归mutex协调逻辑与绘制，删除推迟到回调完成后。修正MapRender类型判断，空栈安全，初始化避免重复线程。Surface销毁先等待渲染线程，再释放画面、调色板与ANativeWindow；EGL和纹理显式释放。Activity暂停时暂停逻辑和播放输出，触摸取消/拖动释放状态。

音频仍使用原项目的NSF方案。背景与音效分开NSF对象，曲目请求在解码线程应用，换曲清缓存；音效不再每次建线程。PCM缓存复制到OpenSL自身buffer，空数据用静音补充，取消跨线程mutex解锁，暂停后销毁OpenSL对象。音效当前以约1.024秒的最大混音窗口处理，精确结束事件仍待接入。

## 验证记录

主机测试 `tools/test_host.py`
使用小型Android图形/声音接口替身，执行真实C++资源和游戏逻辑，开启AddressSanitizer与UndefinedBehaviorSanitizer。角色贴图以 [2026-10-22复核记录](sprite_review.md)
为准。

已验证：

- 5,544个普通精灵姿态与ROM实际6502例程生成的OAM渲染逐像素一致，覆盖11组CHR、63类图像、四向、两帧，包含模型50。
- 1,353个特殊/系统模型组合的位置、透明、翻转、颜色和覆盖顺序与原ROM例程一致；主角实际路径使用模型09。
- 2,041张旧图像/派生图像解码一致；起名页不再使用旧整图背景，避免控件与贴图重叠。
- 主角、脚本NPC、被推动NPC的移动时长分别按8tick、32tick、8tick验证；NPC动作2真实移动且出现第二帧，锁定朝向和禁用步态标志生效。
- 事件08的两种文本分支、场景切换关闭对话、装备数值变化与恢复物品消耗。
- 277条剧情脚本生成结果无 `k_unsupported` 节点；控制、菜单、区域触发、音乐、图块覆盖、玩家/NPC过场动作进入VM执行路径。
- 保存/读取、坏CRC存档拒绝、商店购买、世界入口进入地图1、碰撞与切图亮度范围。
- 240张地图缓存与精灵绘制，完全在屏幕外的位图裁剪；战斗胜利只结算一次。
- 当前NDK29 arm64原生库和Android Java编译通过。
- Debug APK打包与签名成功，含arm64原生库、DEX和导入资源。
- 回归覆盖角色物品/装备不再固定主角：二号角色入队后装备只改变二号角色攻击，主角攻击保持不变；未入队角色初始物品不会被判定为队伍持有。
- 回归覆盖战车系统：原始NO.1位置和装备初始化、地图上车/下车、牵引跟随、战车装备替换、战车状态/装备界面渲染均通过。
- 回归覆盖战斗内操作：步战中角色使用恢复物品、战斗内更换人物装备，车战中使用车载道具恢复SP、战斗内更换战车装备。
- 回归覆盖商店和计算机：战车/人类商品购买、旅馆恢复、装甲片售货机、点唱机、明奇/按摩、修车、底盘改装、赌博机、时空传送机和直接列表服务入口均通过。
- 回归覆盖启动流程：splash渲染、起名页渲染、默认名确认、进入主角家地图3并加载开场NPC组240。

489个原始maps数据及头文件保持原路径、原始字节；原全局调色板也已恢复。工具运行前后校验maps内容未改写。主机截图在同级
`metalmax-analysis/host-tests/`。

`tools/build_debug.py` 已按当前工程的Gradle8.12、AGP8.10.1、SDK35和NDK29构建，使用Android

## 尚未完成的范围

基础战斗公式、逃跑概率、每级成长和恢复物品效果是明确的重制基础规则，目前不是原版6502规则的完整移植。战斗当前仍是单怪物目标和简化敌方回合；怪物AI、技能、状态异常、战车装备损坏、精确SP伤害公式、改装、出租战车完整规则、完整装备特殊效果和所有音频指令未完成。

剧情指令已不再因未知opcode停机；但部分系统效果仍是重制版基础实现或表现近似。改装数值、出租车押金/归还细节、赌博概率和奖品、控制室密码校验、结尾流程、复杂动画的逐帧时序、原版战斗公式和所有音频指令仍需继续按6502行为细化。原始数据和分析材料均已保存，未将这些近似实现当作原版完整复刻。

宝藏中编码大于物品范围的奖励没有直接当物品领取，避免发放错误数值。地图贴图差异遵从用户要求保留，未重新生成或替换。Android真机GPU输出、触控多指组合和音频听感还需要设备验证；主机测试不替代这些硬件检查。
